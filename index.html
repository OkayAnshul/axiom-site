The AI, and where it runs

Axiom is built around a language model, and that is the hard part of the app. Not the call — anyone can post a prompt to an endpoint — but everything around it: which model answers, what it is allowed to know, how a rambling conversation becomes an entry worth keeping, and what still works when there is no key at all.

Two providers, chosen at call time

Groq and Gemini sit behind a single interface, routed per request rather than picked once in settings. Each task names the model it wants: the fast cheap one classifies and extracts, the stronger one writes prose a person will actually read.

Sending every job to the best available model is the expensive way to be lazy. Most calls in this app don't need to be clever — they need to be right and quick.

A conversation is not a journal entry

The digester takes a finished session and writes it up in the user's own register — their words, their shorthand — instead of summarising it in the model's. Get this wrong and the entry reads like a customer service email about your own day.

It runs when you leave the conversation, not on a button, because asking someone to decide their day is over is asking them to do the app's job.

What the model is actually told

The prompt is assembled from the memory store, and for a while it was assembled badly — pronouns, fragments and half-sentences were being passed to the model as established facts about the user, which is how a companion starts saying strange things.

Two fixes: a stop list so junk never enters the store, and a debug surface that shows the exact text the model received. Most prompt bugs are invisible until you look at the prompt.

Memory, with provenance on every line

Facts, people, goals, preferences and open loops are extracted from what you say and consolidated so the same thing said five ways doesn't become five memories. Every item shows when it was noticed and how often it has come up.

A companion that claims to remember you but can't show its working is a chatbot with extra steps. All of it is editable, and all of it is deletable.

It degrades instead of breaking

With no key configured there is still a journal: a local digester writes entries, mood classification, patterns, search and crisis detection all run on-device, and nothing asks you to sign up for anything.

The model makes Axiom better. It was never allowed to make it a requirement.

Keys you own, encrypted at rest

The API key is yours, for your account, held in EncryptedSharedPreferences behind a master key in the Android Keystore. Text goes straight from your phone to the provider you chose.

There is no server in the middle, because there is no server at all.

What it does

Journalling apps usually fail the same way: a blank page is intimidating, and there is no reason to come back tomorrow. Axiom starts a conversation instead.

Talk

Say it, don't compose it

Tell the companion how the day went. When you're done, the conversation is digested into a proper journal entry in your own voice and filed for you.

Memory

It remembers, and shows its working

People, facts, goals and preferences are kept in a list you can read line by line — each with where it came from and how often it's come up. Edit or delete any of it.

Open loops

It follows up. Once.

Mention an interview on Tuesday and it asks how it went on Wednesday. Then it lets the subject drop, because a companion that nags is one you stop talking to.

Patterns

Noticed, not diagnosed

Which weekday runs hardest, whether this week reads lighter than last, which people your better days cluster around. Worked out on the device, and it stays quiet when there isn't enough to say.

Voice

Speak, in your own languages

Dictate entries with on-device recognition. Hindi and Hinglish are first-class, not an afterthought — including in search.

Everywhere

Widgets, tiles, and a way out

Home-screen widgets, a Quick Settings tile for a thought you'll lose otherwise, and an encrypted export of the whole journal that you control.

Your journal stays on your phone

There is no account, no server and no telemetry. Nothing is uploaded, because there is nowhere to upload it to. Mood tracking, patterns, search, streaks and the crisis resources all work with the network switched off entirely.

AI features are optional and run on an API key you supply, for an account you own. Only then, and only for something you asked for, does any text leave the device — and it goes straight to that provider, never through us. Keys are encrypted with a key held in the Android Keystore.

Under the hood

Axiom is a single-module Android app in Kotlin, built with a constraint that shaped everything: no server, and most people won't have an API key. So the interesting work is in what runs on the device.

Mood classification without a model file

Multinomial naive Bayes trained on your own labelled entries, on your own device. It trains in milliseconds on a few dozen examples and needs no network.

Because it learns your vocabulary rather than a pretrained one, Hindi, Hinglish and private shorthand work for free. A general sentiment model knows what "terrible" means; this one learns what your bad days sound like.

Semantic search without embeddings

Full-text search answers "which entries contain these words". It can't answer the question people actually ask a journal — when did I feel like this before? — because today's words aren't the words you used then.

TF-IDF with co-occurrence query expansion scores whole-document similarity instead. A bundled sentence encoder would cost 30–100 MB, cold-start slowly, and be weakest exactly where this app can't afford to be: code-mixed writing.

Migrations that repair data, not just schema

Five hand-written Room migrations from a fixed baseline. Two of them fix data: one nulls a field that had been recording the wrong value, choosing honesty over false precision; one deletes junk memories that a bug had been feeding to the model as facts about the user.

That second one carries a frozen copy of the stop list rather than referencing the live one — a migration has to produce the same result on every device forever.

Statistics that know when to be quiet

Every pattern has a threshold below which it says nothing: three samples for a weekday claim, three days in each window for a trend, a mood gap of 0.6 before a difference is worth mentioning.

An app that tells you what it noticed after four entries is guessing, and you'll learn to distrust it. Silence is a feature.

Type-safe navigation

Destinations are @Serializable Kotlin types, not strings. The old string routes shipped a real bug — a screen was renamed and one navigation target kept pointing at a route that no longer existed, silently, because both halves were strings.

The fix wasn't the rename. It was removing the category of bug.

Crisis detection that cannot fail

Plainly-stated distress is matched on-device with no model, no network and no key — because someone in crisis at 3am without an API key configured is exactly the person who must not hit a dead end.

It's tuned for precision over recall on purpose. Wrongly telling someone having a bad Tuesday that you think they're in danger teaches them the app over-reacts, and then they stop telling it things.
